- n8, n16, and e8 cannot be expressions, They can only be a number or a comptime variable name.
- All registers and keywords must be lower-case.
- Other than decimal, numbers can be binary or hex. With prefixes 0b, 0x respectively.
- Comments are //, not ;.

cc can be
    - zero
    - not zero
    - carry
    - not carry

---Opcode instructions mapped to RGBDS---
Load instructions
LD r8,r8                --- r8 = r8
LD r8,n8                --- r8 = n8
LD r16,n16              --- r16 = n16
LD [HL],r8              --- *hl = r8
LD [HL],n8              --- *hl = n8
LD r8,[HL]              --- r8 = *hl
LD [r16],A              --- *r16 = a
LD [n16],A              --- *n16 = a
LDH [n16],A             --- *hram(n16) = a
LDH [C],A               --- *hram(c) = a
LD A,[r16]              --- a = *r16
LD A,[n16]              --- a = *n16
LDH A,[n16]             --- a = *hram(n16)
LDH A,[C]               --- a = *hram(c)
LD [HLI],A              --- *hl++ = a
LD [HLD],A              --- *hl-- = a
LD A,[HLI]              --- a = *hl++
LD A,[HLD]              --- a = *hl--

Leftover for ROM struct allocations
To allocate a constant struct in ROM, you just use the following syntax.
```
coin := Coin{
    normal_value = 6
    multiplier_value = 7
}
```
Dereferencing the address at *coin.normal_value* will then give you the value 6.

```
sign := Sign{
    text = "This way"
}
// sign is 2 bytes, but the text string is stored after the struct finishes.
// That means that the next allocated string will be 10 bytes away from sign.
// To get the size of the string use sign.text.string_size
```

There is no charmap by default. Instead strings are just ascii mapped. The user has to create their own new charmap if they want to change it, any non set character will be ascii. You have to use the with keyword after a string to use your charmap
```
text = "Hello" with my_charmap 
```
